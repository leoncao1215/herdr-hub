# Herdr Hub 工作计划与阶段验收

本文件是仓库内的持久化待办来源，与 [需求及验收标准](requirements-and-acceptance.md) 配套。
每项状态和验收结论由主会话在工作发生时更新；不得仅更新会话待办。

状态定义：待开始、进行中、待验收、需修复、已通过、受阻。
勾选实施任务不代表阶段通过；阶段必须另有两份只读 review 结论与主会话验收记录。

## 阶段提交约定

用户已授权在合适阶段 commit 并推送当前项目的远端仓库。
关键阶段经双 reviewer 验收通过、问题处理及记录落盘后，由主会话提交本阶段相关代码和文档，
正常推送至 `origin`。reviewer 仍只读，不替主会话提交；运行日志、凭据和个人部署信息不入库。
不以推送代替验收，也不将代码推送视作云端部署授权。

## 各关卡的固定记录格式

达到待验收状态后，在 `docs/acceptance/` 下创建对应关卡记录，并在上方状态表链接。
仓库记录不包含个人机器路径、真实设备标识、凭据或原始敏感日志。

- 阶段、范围、需求编号、代码/文档版本或内容摘要。
- 验收标准与逐项证据：执行命令、预期、实际、限制。
- Copilot CLI reviewer：Herdr 会话角色、完成状态、逐项结论、问题与证据。
- Pi Agent reviewer：同样字段，独立得出结论。
- 主会话汇总：分歧、阻塞项、修复内容、复验轮次和剩余限制。
- 关卡结论：通过 / 不通过 / 证据不足 / 受阻；后续依赖是否可以开始。

两个 reviewer 均只读、不得嵌套委派。只启动未收结果、只取得一份报告、
或必要实测仍缺失，都不能把关卡标为通过。
