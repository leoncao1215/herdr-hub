## 验收矩阵

| 标准 | 代码或证据 | 当前结论边界 |
| --- | --- | --- |
| 纯本机独立端点可传输二进制和半关闭 | `direct_binary_stream_survives_directional_eof` | 1 MiB 请求，接收 EOF 后反向发送完整数据及结束标记；只证明 loopback 传输 |
| 禁止 IP 数据路径时，经私有 relay 仍能传输 | `relay_only_binary_stream_survives_directional_eof` | 双端无 IP transport，只配置 loopback relay；非公网中继实测 |
| 未审批身份不能上线 | `relay_rejects_an_unapproved_identity` | 验证库的身份准入钩子与客户端不能上线，不是完整产品审批流程 |
| 撤销使 relay 客户端离线并阻止重新上线 | `relay_revocation_disconnects_and_rejects_reconnection` | 验证 relay 断连；直连的撤销还必须依靠应用关闭连接和租约 |
| 接收端不消费时写入被背压阻塞 | `write_blocks_until_receiver_consumes_data` | 明确限制 QUIC 收发窗口，恢复消费后验证数据；不是整个产品的内存/负载上限证明 |
| WSS 外层 TLS 终止后，内部 relay 握手及业务流可用 | `relay_works_behind_tls_termination_without_skipping_certificate_checks` | 自签测试证书通过显式信任根验证；TLS 终止到本地明文 HTTP，不跳过验证；不是 Azure L7 网关实测 |
| 同端口的两组配对不能跨组使用 | `scoped_relay_routes_do_not_admit_another_pairs_endpoint` | 两个独立注册表；请求头选路，握手端点白名单准入。静态测试路由标识不等于生产授权票据 |
| 成熟协议承担两条路径的加密与流语义 | iroh/QUIC 依赖及方案中的身份绑定说明 | 尚无业务层授权、重放保护、真实 hc 或路径迁移实现 |
| 明确外部依赖与平台限制 | 方案中的 QAD、NAT、TLS 代理和平台说明 | App Service 不提供 UDP/QAD；若目标网络需要额外地址发现设施，需另行授权，不能默认接公共服务 |
| 明确 hc bootstrap 接入边界 | 只读核对既有严格校验；已安装 hc 命令帮助 | 未采集当前 macOS/WSL2 的真实 bootstrap，本机没有已安装的 WSL 发行版；该项仍未验证 |

## 已发现并修正的问题

1. `Builder::empty()` 必须为本实验显式设置 crypto provider。
2. 发布的 1.4.1 relay 客户端覆盖 URL 路径为 `/relay`。
   之前调查到的 main 分支路径前缀支持不能当成发布 crate 的能力；
   已改用该发布版本支持的 Authorization 请求头分流至独立 relay 注册表。
3. 不只记录准入钩子的“拒绝”事件，还检查被拒端点不能上线；
   配对实验增加双方合法传输的正向对照，以及跨注册表连接无法建立的反向检查。

## 不得推导出的结论

- 没有证明跨 NAT P2P、企业网络可达性或 App Service 部署成功。
- 没有证明中继到直连的业务流自动切换；这是 G5 的必验项。
- 没有证明 macOS/WSL2 的 `hc --via` 接入；真实 bootstrap 和 G2/G7 验证仍需完成。
- 没有实现 GitHub OAuth、持久设备身份、连接授权消费、过期/重放防护或生产租约。
- 暂未做生产级内存、容量和长时间稳定性验证。
- “本机探针通过”不自动等于 G1 全部任务通过，更不等于 R1–R12 产品验收通过。
